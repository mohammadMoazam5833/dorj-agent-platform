## T13 — CLI: handle confirmations instead of hanging
Live finding: `dorj-agent run "rm -rf build"` → the agent-server (nova14) correctly pauses the
conversation in WAITING_FOR_CONFIRMATION (destructive-command gate), but the CLI just waits until
the process is killed (`timeout` → rc 143).
- In `nova-platform/cli` (`run` and `chat`): when the conversation status becomes
  waiting_for_confirmation, print the pending action(s) (tool + command) and ask
  «این دستور تأیید شما را لازم دارد. اجرا شود؟ [y/N]» / "This command needs your confirmation. Run it? [y/N]"
  (language by LANG as in T9). y → approve, anything else → reject (use the same agent-server API the
  web UI uses: see NovaAgent `useRespondToConfirmation` / `respond_to_confirmation`).
- Non-interactive stdin (CI) → reject and exit code 5 with a clear message, unless `--yes` was
  given (then approve). Document `--yes` in --help (bilingual).
- e2e (cli.spec.js): in a temp git repo with a `build/` dir, `run "Run exactly: rm -rf build"` with
  stdin closed → exit 5 and build/ still exists; with `--yes` → build/ removed.
- Bump the CLI to 0.4.1, wheel name unchanged pattern.
